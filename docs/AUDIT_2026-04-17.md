## SECTION 8 — KNOWN RISKS + UNKNOWNS

### 🚨 CRITICAL

1. **Sentinel QA-bypass key in source, ENTERPRISE tier.**  
   `lib/config/sentinel-qa-bypass.ts:7` — `cc_sentinel_test_khomssi_2026` short-circuits `verifyApiKey`. Gated only by `NODE_ENV !== 'production'`. If any preview, staging, or ops subdomain ships with `NODE_ENV` unset (Vercel does set this correctly for Production, but Preview uses `production` too — **verify**), the key works for anyone who reads the repo.  
   *Mitigation:* move the bypass behind an explicit `SENTINEL_QA_BYPASS_ENABLED=true` requirement (current behaviour is *opt-out* when `NODE_ENV !== 'production'` — flip to *opt-in*), and confirm `SENTINEL_QA_BYPASS_ENABLED` is unset on Vercel Production+Preview.

2. **5 of 8 Supabase migration files declare tables with no RLS / no policies in-file.**  
   `scan_history`, `payments`, `saas_subscriptions`, `referral_*`, `webhooks` may be readable/writable by anon if RLS wasn't turned on manually in the Supabase dashboard.  
   *Mitigation:* run the two `pg_tables`/`pg_policies` queries in Supabase SQL editor and confirm. Fix any table with `rowsecurity=false`.

3. **6 legacy public API routes hit paid upstreams (Helius, OpenAI) with no auth and minimal rate limiting.**  
   `/api/analyze-contract`, `/api/forensics`, `/api/neural-v4`, `/api/whale-intel`, `/api/live-feed`, `/api/predict`.  
   *Mitigation:* add `withApiAuth` or at minimum Upstash IP-rate-limit. OpenAI is the most dangerous — a single malicious user can burn your balance.

### 🟠 HIGH

4. **11 critical + 14 high npm vulnerabilities.**  
   Mostly Trezor/protobuf transitive, but `@solana/spl-token → bigint-buffer` is genuinely in your runtime.  
   *Mitigation:* replace `@solana/wallet-adapter-wallets` with a narrower set (you probably only use Phantom + Solflare); evaluate bumping `@solana/spl-token`.

5. **Stripe webhook signature verification — unverified in this audit.**  
   Head of `/api/stripe-webhook/route.ts` was not fully read. If `Stripe.webhooks.constructEvent` is not called, anyone who knows your endpoint URL can POST fake events and upgrade themselves to Enterprise.  
   *Mitigation:* verify within 5 minutes by reading lines 1-100 of that route.

6. **`.gitignore` contains the literal value of a (now-revoked) API key.**  
   Cosmetic once revoked, but humiliating. Remove the two `cc_live_GWzmrn7YWdwRNJ0pyrPwjr5W0jTrSg9E` lines.

7. **No automated tests for business logic or RLS.**  
   Any refactor can silently break webhook → tier sync → entitlement. Zero safety net.  
   *Mitigation:* one Vitest suite for `terminal-reducer`, `api-key.service`, and `intelligence.fetch-token-intelligence` unblocks most of this.

## SECTION 10 — EXECUTIVE SUMMARY

### Top 5 strengths

1. **Production is healthy and auth is enforced.** `/api/health` is green across DB, Helius RPC, and Redis in <40 ms. `/api/v1/ping` correctly returns 401 without a key. The basics are solid.
2. **TypeScript hygiene is exceptional for a 48-hour sprint.** Zero `@ts-ignore`, zero TODO/FIXME/HACK in 2026 lines of code, near-zero `any`, and `tsc --noEmit` is clean. That's rare.
3. **Clean separation of auth + billing + scanning services.** `lib/services/{api-key, subscription, saas-entitlement, rate-limit}.service.ts` form a real service layer; `/api/v1/*` routes are thin adapters. This pays off every time you add a route.
4. **The intelligence terminal Phase-D deliverable is cohesive.** Design tokens, error boundaries per card, reduced-motion support, ticker polling, keyboard shortcuts — it's all wired and type-checks cleanly. Bundle is 200 kB which is reasonable for a rich dashboard.
5. **The built client bundle contains zero server secrets.** Explicit `helius-server.ts` + `server-only` imports are paying off.

### Top 5 risks

1. **A static ENTERPRISE-tier bypass key lives in source and is gated by `NODE_ENV` alone.** One misconfig = full product access for anyone with repo read.
2. **5 of 8 Supabase migration files declare tables with no RLS in the committed SQL.** If those tables were never manually secured in the dashboard, anon clients can read/write `scan_history`, `payments`, `saas_subscriptions`, `referral_*`, `webhooks`. This is a **potential data leak — verify tonight**.
3. **6 legacy public API routes hit paid upstreams (Helius, OpenAI) with no auth.** A single bad actor with `/api/analyze-contract` can drain your OpenAI balance overnight.
4. **Stripe webhook signature verification is unverified in this audit.** If missing, anyone with the webhook URL can forge Enterprise upgrades.
5. **Zero automated tests on the entire business logic — including the webhook → subscription-tier sync.** The next regression ships silently to paying customers.

### Top 5 recommendations — "10 hours this week"

Ranked by impact/effort. If you had 10 hours, spend them here:

1. **(1 h) Invert the QA-bypass gate.** Change `sentinelQaBypassEnabled()` to require `SENTINEL_QA_BYPASS_ENABLED === 'true'` *AND* `NODE_ENV !== 'production'`. Default closed. Kills the single worst finding with a 3-line change.
2. **(1 h) Run the RLS verification queries in Supabase.** Patch any table with `rowsecurity=false` via a single migration SQL. This is the highest-EV hour of your week.
3. **(1 h) Read `app/api/stripe-webhook/route.ts` lines 1-100; confirm `stripe.webhooks.constructEvent` is called. If not, add it.** If a forged webhook can upgrade subscriptions, everything else is moot.
4. **(2 h) Lock down the 6 legacy Helius/OpenAI routes.** Either delete them (if the new `/api/v1/*` routes have superseded them) or wrap with `withApiAuth`. Start with `/api/analyze-contract` — that's OpenAI money.
5. **(5 h) Stand up Vitest + 3 critical tests:**
   - `api-key.service.verifyApiKey()` — happy path + QA-bypass off + malformed key
   - `stripe-webhook` event handler — checkout.session.completed + subscription.deleted
   - `terminal-reducer` full scan flow (already have a script — port to vitest)
